# FinApp subscription-detector

Сервис относится к модулю 1 и выполняет алгоритмический batch-анализ регулярных платежей.
Это не отдельная нейросетевая модель: входом служат уже сохранённые и категоризированные транзакции,
а решение принимается по периодичности, близости суммы, названию контрагента, признакам категории,
смежной пользовательской активности и обратной связи пользователя.

• Берёт уже категоризированные транзакции из БД
• Ищет регулярные платежи и подписки
• Считает гибридный индекс использования
• Учитывает смежные траты: кино, спорт, книги, софт и другие контекстные покупки
• Принимает микроопрос по подписке и сохраняет его между пересчётами
• Оценивает нагрузку подписки на месячные расходы
• Обновляет таблицу `subscriptions`
• Генерирует объяснимые рекомендации по регулярным расходам

## API

- `GET /api/v1/subscriptions` — список найденных подписок с расширенным скорингом.
- `POST /api/v1/analyze-subscriptions` — пересчитать подписки и рекомендации за последние 6 месяцев.
- `POST /api/v1/subscriptions/:id/feedback` — сохранить ответ микроопроса по подписке.

Пример тела для `POST /api/v1/subscriptions/:id/feedback`:

```json
{
  "usage_frequency": "often",
  "importance": "high",
  "decision": "keep"
}
```

Допустимые значения:

- `usage_frequency`: `often`, `sometimes`, `rarely`, `never`.
- `importance`: `high`, `medium`, `low`.
- `decision`: `none`, `keep`, `remind`, `consider_cancel`, `already_cancelled`, `dismiss`.

## Гибридный скоринг

`usage_index` остаётся в диапазоне `0..1`, чтобы не ломать существующих клиентов. Дополнительно сервис отдаёт:

- `subscription_confidence` — уверенность, что регулярный платёж является подпиской.
- `recommendation_confidence` — уверенность в следующем действии.
- `budget_impact` — доля месячных расходов, которую занимает месячный эквивалент подписки.
- `related_activity_index` — косвенные признаки использования по смежным транзакциям.
- `user_feedback_score` — нормализованный ответ пользователя, если микроопрос уже был пройден.
- `status` — итоговое состояние: `healthy`, `confirmed_useful`, `needs_feedback`, `consider_cancel`, `optimize_budget`, `user_cancelled`.
- `recommendation_type`, `evidence_summary`, `next_action` — объяснение и безопасное следующее действие.

Главный принцип: смежные траты повышают уверенность, но не являются жёстким доказательством использования.
Например, попкорн рядом с подпиской на онлайн-кинотеатр увеличит `related_activity_index`, но при дорогой подписке
система всё равно может попросить пользователя уточнить частоту использования.
